# 第一部分：引言 (Introduction)

## 1.1 编写目的

本文档为 **中国农业大学（CAU）校园二手交易微信小程序** 项目提供全面的功能需求与非功能需求规范。本文档的目标读者包括：

- **项目开发团队**：作为系统设计、编码实现的技术依据。
- **项目测试团队**：作为编写测试用例、验收系统功能的基准文档。
- **项目评审人**：作为确认需求范围、评估项目可行性的参考文件。

## 1.2 项目背景

中国农业大学拥有东校区（学院路）和西校区（圆明园路）两个主要校区，两校区之间相距约10公里。在校学生及教职工在日常学习生活中产生大量闲置物品（如教材教辅、数码产品、生活用品等），但缺乏一个安全、高效、专属的校内二手交易平台。

现有的通用二手交易平台（如闲鱼）存在以下痛点：

- 校外人员混杂，交易安全隐患大。
- 缺乏校园身份认证，信任成本高。
- 无法满足东西校区之间的资源流转需求。

因此，本项目拟开发一款基于微信小程序的校园二手交易平台，旨在为CAU师生提供一个 **实名认证、安全可靠、仅限校内面交** 的闲置物品流转社区。

## 1.3 项目范围

### 包含范围 (In Scope)

- CAU校园邮箱（`cau.edu.cn`）实名认证系统。
- 商品发布与管理（含图文上传、分类、定价）。
- 商品浏览、搜索与多维筛选。
- 求购信息发布与响应。
- 站内即时通讯（私聊）。
- 动态取货码核销交易闭环。
- 东西校区属地化展示与跨区交易意向标识。
- 用户诚信分与校园风控系统。
- 个人中心（我的发布、我的买到、信用记录）。
- 数据统计与报表功能（按日/周/月及自定义时间段统计运营数据）。

### 暂不纳入范围 (Out of Scope / Won't Have)

- **线上支付功能**：平台不接入任何支付接口，不参与资金结算，所有交易均为线下见面后私下转账。
- **物流配送系统**：平台不提供任何形式的快递、邮寄或配送服务。
- **烟台研究院、三亚研究院、涿州教学实验场**等异地研究院的支持（列入后续版本规划）。
- **平台介入的托带物流链**：跨区交易中的物品运输由用户自行协商解决，平台仅提供意向标识。
- **评价图片上传**：初版评价仅支持文字评分，不支持图片评价。

# 第二部分：任务概述 (Overall Description)

## 2.1 产品视角

本系统是一款运行在 **微信小程序** 环境中的轻量级应用，后端依赖云服务（如微信云开发或独立后端服务器）。系统作为 **独立的校园服务平台** 运行，不依赖其他外部业务系统。

## 2.2 用户特征

| 用户角色             | 特征描述                                              | 技术水平             |
| -------------------- | ----------------------------------------------------- | -------------------- |
| CAU在校本科生/研究生 | 年龄18-30岁，具备闲置物品交易的核心需求，活跃于校园内 | 熟练使用微信及小程序 |
| CAU教职工            | 有二手交易或闲置处理需求，活跃于东西校区              | 一般                 |
| 平台管理员           | 负责内容审核、用户申诉处理、数据统计                  | 较高                 |

## 2.3 运行环境

- **客户端**：微信小程序，兼容 iOS 和 Android 系统，适配不同屏幕尺寸（含刘海屏与长屏）。
- **服务端**：微信云开发 / 独立后端服务器。
- **约束条件**：须严格遵守《微信小程序平台运营规范》，特别是涉及社交和交易类目的审核要求。

## 2.4 约束条件

- 所有用户必须通过 `cau.edu.cn` 邮箱验证方可使用核心交易功能。
- 平台不涉及任何在线资金交易，不接入支付接口。
- 所有交易必须基于线下校园面交完成，禁止发布需邮寄的商品。
- 用户个人信息（手机号、微信）在交易完成前默认隐藏。

# 第三部分：系统功能需求 (Functional Requirements)

---

## 3.1 模块一：用户接入与身份认证

### 3.1.1 功能目标

- 建立用户与微信生态的关联。
- 验证用户真实的 CAU 校园身份。
- 根据认证状态分配系统操作权限。

### 3.1.2 认证策略：双轨制分级认证

系统采用 **三级权限分级** 机制，根据认证深度开放不同权限：

| 认证级别      | 达成条件                         | 拥有权限                                        | 安全等级 |
| ------------- | -------------------------------- | ----------------------------------------------- | -------- |
| 游客 (L0)     | 微信一键登录（仅获取 OpenID）    | 浏览商品、搜索、查看公共公告                    | 低       |
| 校园校友 (L1) | 通过 `xxx@cau.edu.cn` 邮箱验证 | 收藏商品、发布留言咨询、发布低价商品（< 200元） | 中       |
| 诚信校友 (L2) | 邮箱验证 + 补充学号姓名/证件核验 | 发布任意价格商品、购买商品、获得"认证校友"标识  | 高       |

### 3.1.3 详细功能点

#### F1.1.1 微信一键授权登录

- **动作**：用户首次打开小程序，触发微信登录授权弹窗。
- **处理**：系统调用 `wx.login()` 获取 `code`，后端换取 `OpenID` 作为用户唯一标识。
- **输出**：创建基础用户档案（头像、昵称、所属校区预选）。

#### F1.1.2 CAU 专属邮箱验证

- **输入校验**：系统强制要求输入以 `@cau.edu.cn` 结尾的邮箱地址。
- **正则约束**：`^[a-zA-Z0-9._%+-]+@cau\.edu\.cn$`
- **验证码发送**：后端调用 SMTP 服务发送 6 位随机验证码至 CAU 邮箱。
- **防爆破机制**：
  - 同一邮箱 60 秒内仅能发送 1 次验证码。
  - 同一设备/OpenID 每天尝试验证码上限为 5 次。
- **验证码时效**：有效期为 5 分钟。
- **身份唯一性**：一个 `cau.edu.cn` 邮箱（或提取出的学号）在数据库中仅能绑定一个微信 `OpenID`，防止一人多号。

#### F1.1.3 账户安全与密码管理 (Basic Requirement)

- **微信账号绑定**：系统初始通过微信 OpenID 识别身份，用户可在设置页绑定手机号。
- **独立二级密码**：用户可设置独立于微信的 6 位二级密码，用于确认订单或修改敏感信息。
- **密码修改流程**：支持通过绑定的 CAU 邮箱接收验证码进行密码重置，确保账号在微信丢失时仍可找回。

#### F1.1.4 权限分级自动切换

- 当后端 `auth_level` 从 L0 升级至 L1 或 L2 时，前端需立即刷新 UI（如显示"发布"按钮）。
- **有效期追踪**：系统记录认证成功日期，针对毕业生，系统在每年 7 月触发一次"身份确认"弹窗。

#### F1.1.5 校区引导选择

- 认证成功后，引导用户选择所属校区（**东校区** / **西校区**）。
- 系统根据用户选择的校区，在首页商品流中优先推送同校区商品。

### 3.1.6 异常处理

| 异常场景                 | 处理方式                                               |
| ------------------------ | ------------------------------------------------------ |
| 用户拒绝微信授权         | 跳转至"游客模式"预览页面，在用户尝试发布时再次引导授权 |
| 邮箱无法收信             | 提示用户检查"垃圾箱"或确认邮箱是否是 CAU 官方别名邮箱  |
| 验证码超时               | 提示用户重新获取验证码                                 |
| 身份冲突（邮箱已被占用） | 提供"申诉"入口联系管理员处理                           |
| 邮箱验证失败次数过多     | 临时锁定该邮箱的验证功能，24小时后自动解锁             |

### 3.1.7 数据要求

| 字段名        | 类型    | 约束         | 说明                           |
| ------------- | ------- | ------------ | ------------------------------ |
| user_id       | String  | 唯一, 非空   | 微信 OpenID                    |
| email_address | String  | 唯一         | 完整 CAU 邮箱地址              |
| student_id    | String  | 可选         | 学号（手动补充或邮箱前缀提取） |
| auth_level    | Enum    | [0, 1, 2]    | 当前认证等级                   |
| campus_area   | Enum    | [East, West] | 所属校区                       |
| is_staff      | Boolean | 默认 false   | 是否为教职工                   |
| auth_date     | Date    | -            | 最近一次认证成功日期           |

## 3.2 模块二：商品发布与管理

### 3.2.1 功能目标

- 提供简洁高效的商品发布表单。
- 支持校园特色的发布选项（赠送模式、学院标签、校区交付点）。
- 通过分类和状态管理，确保商品信息的时效性与可搜索性。

### 3.2.2 详细功能点

#### F2.1.1 多媒体信息采集

- **图片上传**：支持 1-9 张图片上传，提供预览、拖拽排序、删除功能。
- **图片压缩**：前端在上传前进行压缩处理，限制单张 < 2MB。
- **视频支持**：支持上传 15 秒以内的短视频（可选功能）。

#### F2.1.2 结构化商品属性

- **标题**：必填，20 字以内。
- **描述**：必填，支持换行，可包含成色说明（如：全新/九成新/功能完好）。
- **价格**：必填，正数，保留两位小数。
- **议价开关**：设置"**能否砍价**"（Negotiable）开关，减少不必要的沟通成本。
- **商品分类**：
  - 教材教辅（可细分至学院级别）
  - 实验器材
  - 数码周边
  - 生活用品
  - 电动车/单车
  - 服饰鞋包
  - 其他
- **商品成色**：全新 / 九成新 / 七成新 / 功能完好 / 其他

#### F2.1.3 "免费赠送"模式 (Green Cycle)

- **交互设计**：在价格输入框旁设置"**0元赠送**"快捷开关。
- **逻辑处理**：
  - 勾选后，价格字段锁定为 0。
  - 商品列表页显示专属的"**赠送**"（Free）绿色标签，区别于普通交易。
- **设计初衷**：鼓励毕业季物资流转（旧书、衣架、收纳盒等），提升社区活跃度与人情味。

#### F2.1.4 学院/专业定向标签 (Department-Specific)

- **标签选择器**：用户发布商品时可从 CAU 官方学院列表中选择关联学院。
  - 示例学院：农学院、植保学院、动科学院、动医学院、信电学院、工学院、经管学院、人发学院等。
- **逻辑处理**：
  - 搜索和筛选中增加"**学院**"维度。
  - 学生找专业课教材时，可直接筛选对应学院，过滤无关信息。
- **数据项**：`target_college` (Enum)，关联 CAU 官方学院列表。

#### F2.1.5 短期租赁模式 (Rental Mode)

- **场景定位**：针对低频、短期刚需物品（如四六级考试耳机、毕业季正装、单反相机等），支持“只租不卖”。
- **专属表单字段**：
  - **租金设置**：按天/按次计费（如：5元/天，或10元/次）。
  - **押金设置**：填写预期押金金额。
  - **免押金门槛**：卖家可勾选“校园诚信分 > 110分可免押金”，利用系统风控降低交易门槛。
- **视觉标签**：租赁商品在列表页会有专属的黄色 `[租赁]` 标签，且首页提供独立的“校园租赁”筛选入口。

#### F2.1.6 校园交付偏好 (CAU Specific)

- **校区选择**：东校区 / 西校区 / 均可。
- **常用交易点勾选**：
  - **东校区**：奥运场馆、一号公寓、王子楼、东南门等。
  - **西校区**：主楼、理学院、宿舍区、校门口、新教等。
  - **自定义**：支持填写具体宿舍号或教学楼名称。

#### F2.1.7 AI 辅助增强（预留接口）

- **智能分类推荐**：用户上传图片或输入标题后，后端调用模型自动推荐最可能的分类。
- **商品描述自动生成**：用户上传图片并输入关键词，AI 利用大语言模型接口生成商品介绍，包含成色评估和规格建议。
- **违规内容检测**：利用 OCR 或图像分类模型，自动拦截包含联系方式（防绕行）、违规广告或不雅内容的图片。

### 3.2.3 商品状态机 (Item Lifecycle)

```
草稿 (Draft) ──→ 上架 (Active) ──→ 锁定中 (Reserved) ──→ 已售 (Sold)
                      │                                       ↑
                      │                                     交易失败
                      └────────→ 下架 (Inactive) ──────────────┘
```

| 状态              | 说明                                             |
| ----------------- | ------------------------------------------------ |
| 草稿 (Draft)      | 用户编辑中尚未发布                               |
| 上架 (Active)     | 商品正在展示中，可被搜索到                       |
| 锁定中 (Reserved) | 已有买家确认想要并进入面交流程，其他人不可再下单 |
| 已售 (Sold)       | 交易完成，进入历史库                             |
| 下架 (Inactive)   | 卖家自行下架或被管理员屏蔽                       |

- **自动下架**：商品默认有效期为 30 天，到期后自动下架，防止过期信息堆积。

### 3.2.4 异常处理

| 异常场景           | 处理方式                                        |
| ------------------ | ----------------------------------------------- |
| 发布频率超限       | 同一用户 1 分钟内只能发布 1 条，防止脚本刷屏    |
| 图片违规           | AI 检测到违规时，发布按钮置灰并弹出提示说明原因 |
| 必填项缺失         | 点击发布时高亮对应表单项并提示                  |
| 用户未认证尝试发布 | 引导跳转至邮箱认证页面                          |

| 字段名         | 类型    | 约束               | 说明             |
| -------------- | ------- | ------------------ | ---------------- |

| title          | String  | 必填, Max 20 字符  | 商品标题         |
| description    | Text    | 必填, Max 500 字符 | 商品描述         |
| price          | Decimal | > 0                | 售价，0 表示赠送 |
| is_negotiable  | Boolean | 默认 true          | 是否接受议价     |
| is_free        | Boolean | 默认 false         | 是否为 0 元赠送  |
| category       | Enum    | -                  | 商品分类         |
| condition      | Enum    | -                  | 商品成色         |
| target_college | Enum    | 可选               | 关联学院标签     |

## 3.3 模块三：求购与信息互助

### 3.3.1 功能目标

- 允许买家主动发布需求，变"搜寻"为"等待响应"。
- 针对教材、实验模版等学术资源提供专门的处理逻辑。
- 通过标签匹配实现"需求找人"。

### 3.3.2 详细功能点

#### F3.1.1 求购信息发布

- **发布表单**：
  - **求购标题**：如"求大一动科专业课教材"、"求生化实验报告模版"。
  - **预期价格**：支持填写具体金额或勾选"**价格面议/好商量**"。
  - **紧迫程度**：增加"**急需**"标记，在列表中高亮显示。
- **分类关联**：强制关联学院和校区，方便潜在卖家精准发现。
- **资源类型标签**：教材 / 实验模版 / 电子资料 / 生活用品 / 其他。
- **资料类型**：电子版 / 纸质版。
- **合规性声明**：发布求购学术资料时，系统弹出强制勾选框——"我承诺求购资料仅用于学术参考，不用于作弊等违规行为"。

#### F3.1.2 "我有"响应机制

- **交互逻辑**：在求购帖详情页设置醒目的"**我有它**"按钮。
- **处理逻辑**：卖家点击后，系统自动引导卖家发送自己已发布的对应商品链接，或直接跳转至私聊界面。
- **设计初衷**：缩短撮合路径，让有货的人能快速"精准投喂"。

#### F3.1.3 求购瀑布流

- **独立入口**：首页设置"**闲置广场**"与"**求购大厅**"两个切换页（Tab）。
- **智能推送**：当卖家发布商品时，系统自动检测"求购大厅"中是否有匹配的求购需求，若有则提示卖家："现有 N 位同学正在求购此类物品，去看看吗？"

#### F3.1.4 求购帖生命周期

- 求购帖默认有效期为 **7 天**，过期自动隐藏。
- 用户可手动点击"**续期**"重新激活求购帖（每次续期延长 7 天）。

### 3.3.3 异常处理

| 异常场景     | 处理方式                                                 |
| ------------ | -------------------------------------------------------- |
| 重复发布     | 检测同用户在 24 小时内发布标题高度相似的求购帖，予以拦截 |
| 求购帖过期   | 自动隐藏，用户可手动续期                                 |
| 违规求购内容 | 关键词过滤拦截（如"代写"、"代考"等）                     |

## 3.4 模块四：交易闭环与隐私安全

### 3.4.1 功能目标

- 建立买卖双方的沟通渠道，保护用户隐私。
- 管理交易状态，确保商品流转闭环。
- 降低交易风险，提供纠纷预防机制。

### 3.4.2 隐私保护逻辑

#### F4.1.1 站内即时通讯

- 买家点击"想要"后，开启基于 OpenID 的**站内即时通讯 (IM)**。
- 支持文字消息、图片消息发送。
- **快捷短语**（校园场景内置）：
  - "同学你好，东西还在吗？"
  - "东校区哪里见面方便？"
  - "可以稍微便宜点吗？"
  - "我下课了，现在可以面交。"

#### F4.1.2 隐私遮蔽

- 在商品详情页，卖家的手机号/微信号默认以 `138****5678` 形式隐藏显示。
- 系统默认 **不展示** 用户微信和手机号，买卖双方通过站内 IM 沟通。
- 只有在双方达成交易意向后，才可选择性地向对方披露真实联系方式（作为备用）。

### 3.4.3 动态取货码系统

#### F4.2.1 凭证生成

- 当买卖双方在聊天窗口点击"**确认交易/面交**"后，系统为买家生成一个唯一的 **4 位数字取货码**。
- 该码关联当前的 交易订单号码，有效期设定为 24 小时。

#### F4.2.2 离线凭证（支持代领）

- 买家可一键生成"**取货凭证卡片**"（包含商品缩略图、交易地点、取货码）。
- 买家可截图发给舍友或委托人，委托人凭此与卖家对接取货。

#### F4.2.3 卖家核销

- 见面后，卖家在小程序界面输入买家提供的 4 位数字取货码。
- **校验逻辑**：匹配成功 → 商品状态自动从 `RESERVED` 变更为 `SOLD`。
- **即时通知**：买家手机同步收到"交易已完成"的微信服务通知。

### 3.4.4 交易状态流转

```
待售 (Active) ──┬──→ 沟通中 (Chatting) ──→ 约定面交 ──→ 已锁定 (Reserved)
                 │                                              │
                 │                                         核销取货码
                 │                                              │
                 └──────────────────────────────────────→ 已售出 (Sold)
```

![商品状态流转逻辑图](./item-lifecycle.png)

- **锁定逻辑**：一旦发起"约定面交"，商品自动进入 `RESERVED` 状态，防止一货多卖。
- **防鸽子机制**：若卖家 24 小时内未确认完成交付，系统自动询问是否交易失败并建议重新上架。

### 3.4.5 租赁履约与状态流转 (Rental Lifecycle)

租赁业务区别于一次性买卖，需要完整的“借出-归还”闭环，且押金和租金的交收均在线下完成。

#### F4.3.1 双重核销机制

- **第一阶段（借出核销）**：双方见面查验物品（如耳机是否出声）并线下转交押金/租金后，卖家输入买家的“借出核销码”，物品状态变更为 `Renting` (租赁中)，系统开始计时。
- **第二阶段（归还核销）**：租期届满，双方再次碰头，卖家检查物品无损坏并退还线下押金后，买家输入卖家的“归还确认码”，订单变更为 `Completed` (已完结)。

#### F4.3.2 逾期与损坏风控

- **超期提醒**：租期结束前 12 小时，系统自动通过微信服务通知提醒双方。
- **违约惩罚机制**：
  - 若买家逾期拒不归还，或造成物品严重损坏且拒绝赔偿，卖家可凭聊天记录和线下转账截图发起“租赁仲裁”。
  - 经管理员核实，违约方将被**直接扣除 50 校园诚信分**（触发严重受限/黑名单），并公示其部分脱敏信息。

### 3.4.6 东西校区跨区交易策略

#### F4.4.1 跨区意向标签

- 卖家发布商品时可勾选"**支持跨区送货/托带**"。
- 在商品详情页显著位置显示标签：`[支持东西校区互带]`。
- **设计初衷**：仅作为"信号"告知买家——虽然商品在西区，但卖家可以想办法送到东区。

#### F4.4.2 私聊协商

- 当买家看到跨区商品并点击"想要"时，直接进入私聊界面。
- **强制提醒**：私聊窗口顶部固定提示：
  > "该商品位于不同校区。平台不提供配送服务，请双方私下协商交付方式。跨区交易风险自担。"
  >

#### F4.4.3 交付确认

- 无论卖家亲自送还是托人带，最终以 **取货码核销** 作为所有权转移的最终节点。
- **责任界定**：核销成功后，平台即认为物品已安全送达。

### 3.4.7 安全与纠纷预防

#### F4.5.1 安全交易贴士

在聊天窗口顶部循环滚动：

> "本校仅限面交，请务必在食堂、图书馆等公共场合进行交易，切勿提前线上转账！"

#### F4.5.2 举报入口

在沟通界面右上方设置明显的"**举报**"按钮，举报类型包括：

- 放鸽子（确认面交后单方取消）
- 物品与描述严重不符
- 言语骚扰
- 疑似校外人员

#### F4.5.3 举报存证

- 举报时强制要求上传 1-3 张聊天记录截图或实物对比图。
- 系统后台记录关键交易确认动作的时间戳，作为纠纷仲裁依据。

### 3.4.8 异常处理

| 异常场景            | 处理方式                                             |
| ------------------- | ---------------------------------------------------- |
| 取货码错误输入 3 次 | 锁定交易 10 分钟，防止暴力破解                       |
| 交易取消            | 双方均可发起，需选择原因。系统记录取消次数计入诚信分 |
| 异地交易未核销      | 超 24 小时取货码自动失效，系统引导双方重新沟通       |

### 3.4.9 数据要求

| 字段名             | 类型     | 约束       | 说明                             |
| ------------------ | -------- | ---------- | -------------------------------- |
| chat_session_id    | BigInt   | 唯一, 非空 | 会话 ID                          |
| transaction_id     | BigInt   | 唯一, 非空 | 交易订单 ID                      |
| secure_token       | String   | 4位数字    | 取货码（加密存储）               |
| token_status       | Enum     | -          | [未使用, 已核销, 已过期, 已作废] |
| agreed_location    | String   | -          | 双方约定的面交地点               |
| is_cross_campus    | Boolean  | 默认 false | 是否为跨校区交易                 |
| cross_campus_label | Boolean  | 默认 false | 卖家是否勾选了"支持跨区"         |
| finish_time        | DateTime | -          | 交易正式结束时间                 |

## 3.5 模块五：个人中心与风控管理

### 3.5.1 功能目标

- 量化用户诚信度，为交易双方提供参考。
- 建立自动化阶梯式处罚机制。
- 提供管理工具，维护社区秩序。
- 提供“最近浏览”入口，保存并展示用户最近点击过的 20 个商品。

### 3.5.2 校园诚信分 (Campus Credit)

#### F5.2.1 初始值与构成

- 新认证用户初始诚信分为 **100 分**。
- **加分项**：
  - 完成一次好评交易：+2 分。
  - 连续 7 天无违规发布：+1 分。
- **减分项**：
  - 放鸽子（确认面交后单方取消且被举报核实）：**-10 分**。
  - 描述严重不符（被举报属实）：**-20 分**。
  - 发布违规内容（色情、赌博、违禁品）：**直接清零**。
  - 托带过程中造成物品丢失或损坏：**-30 分**。
  - 租赁逾期拒不归还：**-50 分**，直接触发封禁机制。
  - 租赁物品人为损坏且拒不协商赔偿：**-30 分**。

#### F5.2.2 阶梯式限权

| 分数区间  | 权益状态 | 限制措施                                          |
| --------- | -------- | ------------------------------------------------- |
| 80-100 分 | 正常     | 权益完全正常                                      |
| 60-79 分  | 受限     | 发布商品数量限制最多 2 个，头像显示"诚信一般"标识 |
| 40-59 分  | 严重受限 | 禁止发布商品，仅保留浏览和求购权限                |
| < 40 分   | 黑名单   | 禁止所有交互操作，需向管理员申诉方可解封          |

#### F5.2.3 透明度

- 用户可在"个人中心"查看自己的信用分数变动轨迹（类似账单记录），明确知道扣分原因。

### 3.5.3 黑名单系统

#### F5.3.1 个人黑名单

- 用户 A 可将用户 B 加入个人黑名单。
- 黑名单中的用户无法查看 A 发布的商品，也无法给 A 发起聊天。

#### F5.3.2 平台级黑名单

- **多点举报触发**：同一用户在 24 小时内被 3 个不同用户举报"骚扰"或"疑似校外人员"，系统自动临时锁定账号，进入管理员待审序列。
- **身份熔断**：一旦某个 `cau.edu.cn` 邮箱被永久封禁，该邮箱及对应学号永久无法再次注册。

### 3.5.4 异常行为监控

- **关键词过滤**：利用简单 NLP 规则拦截包含"代做"、"兼职"、"快递"、"邮寄"等高度疑似违规或非面交的关键词。
- **频率限制**：同一账号每天发布求购或商品的数量不得超过 5 个，防止职业卖家进场。

### 3.5.5 管理员后台功能

| 功能     | 描述                                                       |
| -------- | ---------------------------------------------------------- |
| 内容巡查 | 支持按关键词批量检索并下架违规商品                         |
| 申诉处理 | 针对被扣分或拉黑的用户，提供反馈入口，管理员可手动恢复分数 |
| 数据统计 | 统计东/西校区每日交易量、最热门分类等运营数据              |
| 用户管理 | 查看和编辑用户状态、诚信分、黑名单记录                     |

### 3.5.6 数据要求

| 字段名            | 类型    | 约束       | 说明                     |
| ----------------- | ------- | ---------- | ------------------------ |
| credit_score      | Integer | 0-100      | 用户诚信积分             |
| cancel_count      | Integer | -          | 近 30 天单方取消交易次数 |
| report_log        | Array   | -          | 关联的举报历史 ID        |
| is_banned         | Boolean | 默认 false | 是否处于平台黑名单状态   |
| blacklist         | Array   | -          | 个人黑名单用户 ID 列表   |
| admin_notes       | Text    | -          | 管理员对该用户的备注     |
| last_penalty_date | Date    | -          | 最近一次受罚日期         |

## 3.6 模块六：数据统计与报表分析

### 3.6.1 功能目标

- 监控平台运行状态与健康度。
- 分析用户行为模式（东西校区偏好、热门品类、学院活跃度）。
- 为运营决策与未来盈利规划（如广告位定价）提供数据支撑。

### 3.6.2 详细功能点

#### F6.1.1 实时概览仪表盘 (Dashboard)

- **核心指标卡片**：同时段在线人数、今日新增用户数、今日发布商品数、今日完成核销交易数。
- **趋势图**：采用折线图展示近 7 天的关键指标变化趋势（如日活跃用户、日发布量）。
- **数据粒度**：所有统计支持区分 **东校区** 与 **西校区** 分别查看。

#### F6.1.2 多维度统计报表 (Analytics Reports)

支持按 **日 / 周 / 月 / 自定义时间段** 进行筛选与统计：

- **流量统计**：

  - 各模块页面点击量（求购大厅 vs. 闲置广场 vs. 个人中心）。
  - 搜索关键词频次统计（可用于生成搜索热词云）。
  - 商品详情页浏览量排行。
- **交易统计**：

  - **商品发布量**：按分类维度统计发布比例（如"教材教辅占比 35%"）。
  - **成交率分析**：计算 `成交率 = 已核销订单数 ÷ 总发布数`，判断各类目流转效率。
  - **热门商品类别排行**：按浏览量、收藏量、私聊次数等多维排序。
  - **平均成交周期**：从发布到核销的平均天数，反映商品流转速度。
- **用户行为分析**：

  - **校区活跃度对比**：东校区与西校区的日/周/月活跃用户数对比。
  - **学院热度排行**：各学院用户的发布量、求购量排行。
  - **认证转化率**：从游客(L0)到邮箱认证(L1)再到完全认证(L2)的转化漏斗。

#### F6.1.3 热门榜单分析 (Trending Data)

- **搜索关键词云**：记录用户搜索频次最高的词汇（如"雅思"、"实验报告"、"自行车"），用于优化搜索推荐策略。
- **热门商品榜单**：统计被收藏最多、私聊次数最多的商品 TOP 榜单。

#### F6.1.4 数据导出 (Data Export)

- **功能描述**：支持将统计报表结果导出为 **CSV** 或 **Excel** 格式。
- **设计初衷**：方便运营人员将数据导入数据分析工具（如 Python、R 等）进行更深入的挖掘，或用于项目报告展示。

### 3.6.3 数据埋点与存储 (Data Tracking)

为支撑上述统计功能，系统需在后端记录以下埋点数据：

| 字段名          | 类型    | 说明                                                |
| --------------- | ------- | --------------------------------------------------- |
| stat_date       | Date    | 统计日期                                            |
| campus_id       | Enum    | 区分东西校区的数据标识                              |
| category_click  | JSON    | 各分类点击分布，如 {"textbook": 120, "clothes": 50} |
| total_published | Integer | 当日发布商品总数                                    |
| total_turnover  | Integer | 当日成功核销的商品总数                              |
| active_users    | Integer | 当日活跃用户数                                      |
| new_users       | Integer | 当日新增注册用户数                                  |
| search_keywords | JSON    | 当日搜索关键词及其频次                              |

### 3.6.4 隐私约束 (Privacy Note)

- **数据脱敏**：所有统计报表中的数据必须为脱敏后的聚合数据。
- **禁止个体关联**：后台报表仅展示"某学院活跃人数"等聚合信息，不得直接关联到具体用户的聊天内容或个人隐私信息。
- **权限控制**：统计报表功能仅限管理员角色访问，普通用户不可见。

### 3.6.5 异常处理

| 异常场景                 | 处理方式                                                             |
| ------------------------ | -------------------------------------------------------------------- |
| 统计时段数据为空         | 显示"暂无数据"，而非报错或显示异常数值                               |
| 统计计算超时（数据量大） | 采用预聚合策略（每日凌晨离线计算前一天的统计数据），避免实时计算压力 |

# 第四部分：非功能需求 (Non-functional Requirements)

## 4.1 隐私保护

- **号码遮蔽**：在未达成交易意向前，用户手机号及微信号默认隐藏。
- **图片水印**：所有上传的商品图片，系统自动在右下角合成"CAU 二手交易专用"半透明水印，防止图片被校外爬虫抓取用于诈骗。
- **数据加密**：学生个人信息（如手机号、学号）必须加密存储。
- **聊天记录保护**：站内聊天内容仅交易双方可见，平台不对外公开。

## 4.2 性能要求

系统应根据不同终端设备的硬件算力及操作系统版本，实施针对性的性能控制策略：

| 操作场景                   | 高性能设备 | 主流中端机 | 入门/老旧机 |
| :------------------------- | :--------- | :--------- | :---------- |
| **商品列表页加载**   | <= 0.8 秒  | <= 1.5 秒  | <= 2.5 秒   |
| **搜索/筛选反馈**    | <= 1.0 秒  | <= 1.8 秒  | <= 3.5 秒   |
| **AI 描述生成响应**  | <= 2.0 秒  | <= 3.5 秒  | <= 5.0 秒   |
| **图片水印合成上传** | <= 1.5 秒  | <= 2.5 秒  | <= 4.0 秒   |

- **图片加载**：采用懒加载（Lazy Loading）技术，图片列表滚动时按需加载。
- **并发支持**：系统应支持至少 500 用户同时在线浏览（校园级规模）。

## 4.3 可靠性

- **交易状态一致性**：确保取货码核销、商品状态变更、通知发送的操作具备原子性，防止状态不一致。
- **数据备份**：用户数据和交易记录每日自动备份。
- **自动恢复**：系统故障后应能在 30 分钟内恢复正常服务。

## 4.4 安全性

- **反作弊**：同一邮箱 24 小时内尝试为超过 3 个 OpenID 进行验证时，系统自动锁定该邮箱并报警。
- **防脚本攻击**：发布和验证接口采用频率限制防刷机制。
- **内容安全**：符合《微信小程序平台运营规范》，自动过滤违规内容。

## 4.5 可用性

- **操作简洁**：商品发布流程控制在 30 秒内完成。
- **自动保存草稿**：用户编辑表单过程中若中断（如上课、没流量），系统自动保存已填写内容。
- **无操作门槛**：界面简洁直观，无需用户手册即可上手使用。

# 第五部分：外部接口需求 (External Interface Requirements)

## 5.1 用户界面 (UI) 需求

- **色调**：采用 CAU 校徽色（绿色系）作为主题色，增强校园归属感。
- **布局**：
  - 首页采用瀑布流展示商品图。
  - 底部导航栏：首页 / 求购大厅 / 发布 / 消息 / 我的。
- **适配性**：必须适配不同屏幕尺寸（iPhone 刘海屏、安卓长屏、平板等）。
- **风格**：简洁、清新、年轻化，符合大学生审美。

## 5.2 硬件接口

- **摄像头**：用于拍摄商品图片和学生证认证照片。
- **相册**：支持从相册选择图片上传。
- **定位服务**：可选，用于辅助检测用户是否在校区内（通过微信定位 API）。

## 5.3 软件接口

- **微信登录 API**：`wx.login()` 获取临时 code，换取 OpenID。
- **微信服务通知**：交易状态变更时向用户推送服务通知（可选实现）。
- **云存储 API**：图片和视频文件的上传与存储。
- **SMTP 邮件服务**：用于发送邮箱验证码。

# 第七部分：未来扩展性与盈利预留 (Future Enhancements)

## 7.1 架构可扩展性预留

虽然当前版本不实现商业化功能，但系统架构应预留以下扩展接口：

- **F.E.1 广告位预留**：前端 UI 在首页和分类页预留 Banner 组件的挂载接口，初始状态设为隐藏。
- **F.E.2 权重系统**：后台数据库预留 `priority_weight` 字段，未来可通过简单逻辑实现"付费置顶"或"积分兑换曝光"。
- **F.E.3 商家入驻接口**：用户角色表中预留 `role_type` 枚举值 [Student, Admin, Merchant]，为未来校外商家入驻留出扩展空间。

## 7.2 盈利模式阶梯式规划（仅参考）

| ------------- | -------- | ------------------------------------------------------ |
